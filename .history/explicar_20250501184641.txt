Al dividir el problema y fomentar la reutilización del código, se evita caer en una “crisis” típica de los programas monolíticos:

-------
ignorar extra
---------
Un programa monolítico es aquel que está construido como una sola unidad grande, sin divisiones claras entre sus partes. Todo el código está muy interconectado y mezclado, lo que significa que:
-Si cambiás una parte, podés romper otra sin querer.
-Es difícil de entender y mantener.
-No se puede reutilizar fácilmente.
-Colaborar en equipo se vuelve más complicado.

En cambio, con programación modular, el código se divide en módulos o partes independientes (como funciones, clases o archivos separados), lo que lo hace mucho más organizado y manejable.

diapo 7

El enfoque top-down refleja el mismo principio que sustenta la modularización: abordar la complejidad a través de la organización progresiva. No solo ayuda a mantener una visión clara del sistema completo, sino que también guía el desarrollo paso a paso, evitando errores comunes derivados de la improvisación o la falta de estructura. En definitiva, es una herramienta clave para transformar ideas abstractas en soluciones concretas,


----
en parte se refiere al proceso de tomar conceptos o problemas generales y vagos (las "ideas abstractas") y convertirlos en soluciones claras y detalladas que puedan implementarse de forma práctica y efectiva (las "soluciones concretas").

Por ejemplo, cuando se empieza con un proyecto complejo, lo primero que se tiene son ideas generales sobre lo que se quiere lograr, pero esas ideas aún no están suficientemente definidas para poder ser programadas. Con un enfoque como el top-down, descompones esas ideas generales en módulos más pequeños y específicos, que luego se pueden trabajar, programar y probar por separado.
-----
 manteniendo siempre el control sobre el crecimiento y la coherencia del software.

De esta manera, el diseño top-down permite una descomposición lógica y gradual del proyecto, asegurando que cada etapa esté claramente definida y controlada. Esto facilita la implementación y ayuda a mantener el enfoque, evitando que el proyecto se desvíe de sus objetivos iniciales.

diapo 9

una función es un bloque de código que realiza una tarea específica y puede ser reutilizado en varias partes de un programa. Una función toma entradas (también conocidas como argumentos o parámetros), 

Los módulos de función en Python permiten organizar y reutilizar código de manera eficiente. Al encapsular una tarea en una función, se facilita la legibilidad y mantenibilidad del código, además de permitir su reutilización en diferentes partes del programa. Con una correcta implementación de funciones, el código se vuelve más modular, menos propenso a errores y mucho más fácil de depurar y expandir.

---
extra
….

El cuerpo de una función en Python es el bloque de código que se ejecuta cuando se llama a la función. 

Está indentado debajo de la declaración def y puede contener instrucciones que definan el comportamiento de la función, como cálculos, condiciones, ciclos, entre otros. 

Si la función tiene un valor de retorno, se utiliza la palabra clave return para devolver ese valor.


()

los paréntesis en una función pueden contener parámetros o argumentos que la función necesita para ejecutarse. 

Los parámetros son variables que la función usa para recibir valores cuando se le llama.


--.---
Parámetros: Son las variables declaradas en la función que definen los datos de entrada.

Argumentos: Son los valores reales que se pasan a la función cuando se llama.



Por ejemplo:

def saludar(nombre, edad):
    print(f"Hola, {nombre}. Tienes {edad} años.")

Aquí:
nombre y edad son parámetros.
Cuando llamas a la función, debes pasar los argumentos correspondientes, como en saludar("Juan", 25).


Si una función no necesita parámetros, los paréntesis se dejan vacíos:

def decir_hola():
    print("¡Hola!")
